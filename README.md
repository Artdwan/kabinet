# Кабинет ученика

Веб-приложение для подготовки к ЦТ по математике и химии: домашние задания с интерактивной проверкой,
теория, тренировочные и полные тесты ЦТ, статистика, техники запоминания и мини-тренажёры. Три роли —
ученик, преподаватель, родитель.

Это продакшн-реализация прототипа, изначально собранного в Claude Design (`Kabinet.dc.html`). Прототип
использовал прокси-шаблонный движок и был переписан на React + TypeScript с сохранением визуального
стиля, структуры данных и поведения экранов.

## Стек

- React 19 + TypeScript, Vite
- React Router — маршрутизация по разделам и ролям
- KaTeX — рендеринг формул (с конвертацией из плоской алгебраической нотации исходных данных в LaTeX)
- Recharts — не используется напрямую; графики (динамика баллов, точность по темам) — inline SVG
- Lucide — иконки

## Запуск

```bash
npm install
npm run dev      # dev-сервер
npm run build    # прод-сборка (tsc -b && vite build)
npm run lint      # oxlint
```

Приложение открывается сразу в авторизованном демонстрационном кабинете ученика (Максим, 11 класс).
Через меню профиля можно выйти и войти в демо-аккаунт преподавателя или родителя.

## Архитектура

```
src/
  types/            доменные типы (Homework, Exercise, CtTest, Technique, Trainer, ...)
                     и типы рантайм-состояния (Store)
  data/              контент как данные, а не как разметка компонентов:
                     content.ts   — предметы, темы, теория, домашние работы, тесты ЦТ
                     roles.ts     — роли/аккаунты, группы, техники запоминания, тренажёры
  services/
    storage.ts       обёртка над localStorage
    mockApi.ts       "бэкенд" прототипа: seed/migrate, checkAnswer, solutionAvailability,
                      homeworkProgress — те же сигнатуры, что понадобятся при переходе на реальный API
    StoreContext.tsx React-контекст поверх mockApi: единая точка мутации состояния (mutate())
    actions.ts       операции экрана поверх Store: ответы, подсказки, решения, черновик,
                      рисунок, вложения, сдача работы, прохождение теста, техники, тренажёры
    selectors.ts      производные данные: средний балл, слабые/сильные темы, статус работы и т.д.
    testScoring.ts    подсчёт результата теста ЦТ
  components/         переиспользуемые UI-компоненты (AppShell, MetricCard, ProgressRing,
                      StatusBadge, ContentBlockRenderer, Formula/MathText, ...)
  pages/
    auth/             вход и регистрация с выбором роли
    student/          Главная, Домашние задания (список + читалка), Теория, Тесты ЦТ,
                      Статистика, Техники, Тренажёры (4 мини-игры), Настройки
    teacher/          Обзор, Ученики, Проверка работ, Материалы
    parent/           Прогресс ребёнка, Отчёты
```

Контент (учебные материалы, домашние работы, тесты) полностью отделён от компонентов — новые темы,
задания и материалы добавляются через `src/data`, без изменения экранов.

## Где будет реальный backend

Сейчас весь прогресс ученика (ответы, подсказки, черновики, рисунки, результаты тестов, роли,
настройки) хранится в `localStorage` через `src/services/mockApi.ts` и `src/services/actions.ts`.
Места будущей интеграции с сервером отмечены комментариями `TODO backend:` — среди них:

- `POST /auth/login`, `POST /auth/register` — авторизация и роли
- `PATCH /homeworks/:id/attempts` — сохранение ответов, подсказок, черновика
- `POST /files` — загрузка вложений (сейчас фото/PDF хранятся только как метаданные + dataURL рисунка)
- `POST /homeworks/:id/submit` — сдача работы преподавателю
- `POST /exercises/:id/check` — проверка ответа (сейчас выполняется на клиенте; в бою правильный
  ответ не должен приходить в браузер)
- `POST /ct-sessions/:id/finish` — завершение теста и подсчёт балла
- `POST /homeworks/:id/review` — оценка и комментарий преподавателя
- `POST /analytics/events` — аналитика

Замена `mockApi`/`actions` на вызовы реального API не должна требовать изменений в компонентах —
это и есть смысл разделения на слой данных, сервисный слой и экраны.
